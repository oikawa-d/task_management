# GitHub本文の安全な受け渡し

## 事象

Markdownのバッククォートやシェル記号を含む本文を、二重引用符の`--body`引数へ直接渡すと、シェルが記法をコマンド置換として解釈する。

## 原因

シェルの引用規則とMarkdownの記法を同じコマンド文字列で扱い、本文をデータではなくシェル構文として評価させてしまう。

## 正しい対処

1. `apply_patch`で一時本文ファイルを作成する。
2. `sed`などで本文を目視確認する。
3. `gh pr create --body-file <path>`または同等のファイル入力オプションを使う。
4. 作成後にGitHub上の本文とURLを確認する。

本文ファイルには認証情報や`.env`の内容を含めない。作業完了後の一時本文ファイルは`tmp/`配下に置き、削除してよい。
