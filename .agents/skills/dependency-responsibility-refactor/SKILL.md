# 依存性関数の責務移動における注意点

## 事象

取得処理と認可処理を分離するリファクタリングでは、依存性関数の引数や認可クエリの呼び出し位置が変わる。実装だけを変更すると、テストに古いキーワード引数やモック設定が残り、実行時エラーまたは誤った呼び出し回数の検証を引き起こす。

## 原因

依存性関数の公開シグネチャ、routerの依存解決、serviceの認可責務、単体テストの直接呼び出しを別々に更新してしまうためである。

## 正しい対処

- 変更前に関数の全呼び出し元とテストを検索する。
- 取得と認可の責務を分ける場合、取得側から認可用の依存引数・DB呼び出し・不要なimportを除去する。
- 認可をserviceへ移す場合、許可・拒否・404秘匿・管理者バイパスをserviceテストで確認する。
- 旧キーワード引数、旧モック対象、不要なimportを検索してからpytestとruffを実行する。
- クエリ回数の要件がある場合、認可repositoryのmockに対して`assert_awaited_once_with`等で呼び出し回数を検証する。
