# API実DBテストの実行境界

## 事象

APIの実DBテストをリポジトリルートから実行すると、Alembicが相対パスの`alembic`ディレクトリを見つけられず、fixtureの初期化に失敗する。同じ一時PostgreSQLへ複数のpytestプロセスを並行接続すると、初回マイグレーションの拡張作成が競合することがある。

## 原因

APIのpytest設定とAlembic設定が`api/`をカレントディレクトリとする構成であり、DB fixtureがテストセッションごとに同じデータベースへマイグレーションを実行するため。

## 正しい対処

- APIテストは`api/`を作業ディレクトリとして実行し、テストパスは`tests/`配下で指定する。
- 実DBテストを複数ブランチで検証するときは、同じDBへfixtureを並行実行せず、順番に実行するかブランチごとにDBを分離する。
- 競合が発生した場合は、対象が一時DBであることを確認して再初期化し、単独・順次実行で再検証する。
