# OAuth結合テストの境界モック

## 事象

OAuthのルートからサービス層までを通すテストで、Google・Redis・DBの一部だけを差し替えた結果、共通のRedisレート制限処理が実Redisへ接続し、テストが503で失敗することがある。

## 原因

ルート単体テストでサービスをモックする場合と異なり、サービス結合テストではサービスが呼び出すレート制限、ワンタイム値、ユーザー取得、認証戦略、履歴記録の各境界を個別に準備する必要がある。

## 正しい対処

OAuthのルート・サービス結合テストでは、次をテストごとに明示する。

1. `redis_store.check_rate_limit` を成功値へ差し替える。
2. Google Provider、state/handoff消費、ユーザー取得、認証戦略、履歴記録を外部境界として差し替える。
3. `TestClient`で実際のHTTPルートを呼び、認証モード、リダイレクト、レスポンスCookie、レスポンスボディを検証する。
4. RedisまたはPostgreSQLを実際に起動して検証できない場合は、対象範囲と未検証部分をテスト報告に明記する。
