# シェルテストfixtureの状態管理における注意点

## 事象

テストケースへ一時的な環境変数fixtureを追加した際、次のケースが前のケースの応答データを引き継ぎ、期待する入力条件と異なる状態で実行されることがある。

## 原因

シェルテストは同一プロセス内で環境変数を共有するため、ケース固有のfixtureを設定した後に、後続ケースが必要とするfixtureへ戻すか解除する処理を明示しなかった。

## 正しい対処

- ケース固有の環境変数は、アサーション直後に後続ケースのfixtureへ戻すか`unset`する。
- 新しい異常系fixtureを挿入した場合、直後だけでなく次のケースが参照する環境変数も確認する。
- fixture追加後はテスト全体を実行し、単独実行では見えない状態漏れを検出する。
